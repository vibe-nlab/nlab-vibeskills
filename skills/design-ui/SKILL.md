# NeuroLab Design (shadcn + графит)

## 1. Назначение (Purpose)

Применяет дизайн-систему NeuroLab к shadcn-интерфейсу: сборку UI делает
**оригинальный скилл `shadcn`** (внешняя зависимость — его workflow,
CLI-справочники и обязательные правила композиции живут в нём и обновляются
его автором), чат и прочие AI-специфичные экраны — реестр
**AI Elements** (`https://elements.ai-sdk.dev/docs`, п. 4.5), этот скилл
добавляет поверх фирменные правки: Montserrat на базовых 16px и графитовую
тёмную тему.

> **Мажорное изменение v2.0.0**: скилл больше не содержит копию
> shadcn-документации (`shadcn.md`, `rules/`, `cli.md` и т.д.) — вместо
> этого требуется установленный оригинальный скилл `shadcn`. Один источник
> правды, никакой расходящейся копии.

**Когда вызывать.** До написания первых экранов, а не после. Скилл задаёт
токены темы, шрифт и базовый размер — то, на чём экраны потом строятся.
Применять его к уже собранному фронту означает переделку: цвета окажутся
захардкожены, отступы и размеры подобраны на глаз, компоненты собраны мимо
семантических токенов. Порядок один: сначала дизайн-система, потом экраны.

Макет из `/nlab:prototype` уже нарисован этим же дизайн-языком — он вход,
а не то, что надо перекрашивать.

## 4. Guidance — рекомендации

### 4.1. Шрифт и размер — В ОБЕИХ ТЕМАХ

- **Montserrat**, самохостом:
  ```bash
  npm i @fontsource/montserrat
  ```
  ```ts
  // main.tsx (или входной css): веса 400/500/600/700
  import "@fontsource/montserrat/400.css";
  import "@fontsource/montserrat/500.css";
  import "@fontsource/montserrat/600.css";
  import "@fontsource/montserrat/700.css";
  ```
  Пакет включает cyrillic/cyrillic-ext unicode-range — кириллица работает из
  коробки, проверь после сборки, что подсеты вошли в бандл.
- Токен шрифта (Tailwind v4 / shadcn):
  ```css
  --font-sans: 'Montserrat', sans-serif;
  --font-heading: var(--font-sans);
  ```
- **Размер: базовый 16px — root НЕ масштабируем.**
  ```css
  html { font-size: 100%; }   /* 16px, дефолт браузера — НЕ 112.5% */
  ```
  То есть все rem-размеры Tailwind и shadcn работают в своих штатных
  значениях (`text-sm` = 14px, `text-base` = 16px), под них компоненты и
  нарисованы. Раньше скилл требовал `112.5%` (16px → 18px) — правило
  отменено: масштаб растягивал сетку и отступы вслед за текстом, интерфейс
  получался «зумленным». Крупнее нужен конкретный блок — задавай размер
  ему (`text-lg`, `text-xl`), а не всему документу. Строка с `100%`
  оставляется явно: она показывает, что дефолт выбран сознательно, и по ней
  проверяется, что старое масштабирование никто не вернул.
- Моноширинный шрифт для кода/yaml оставить дефолтным — но везде, где код
  показывается в карточках: `white-space: pre-wrap` + `overflow-wrap: anywhere`
  (длинные токены не должны вылезать за контейнеры; у Badge — `whitespace-normal
  break-words max-w-full min-h-*` вместо `nowrap h-*`).

### 4.2. Тёмная тема — графитовые нейтрали (НЕ дефолтный shadcn-чёрный)

Фон — тёплый графит `#272726` = `oklch(0.272 0 0)`; слои — соседние ступени
серого; текст — белый и приглушённо-белый. Хрома 0 (нейтраль); допустим лёгкий
тёплый/бежевый уклон — chroma до ~0.008 при hue 90–110, если проекту нужна
теплота. Полный набор токенов (вставить в тёмный блок темы — `.dark` или
`:root`, если проект dark-first):

```css
--background: oklch(0.272 0 0);            /* #272726 */
--foreground: oklch(0.985 0 0);            /* белый */
--card: oklch(0.32 0 0);                   /* панель — на тон светлее фона */
--card-foreground: oklch(0.985 0 0);
--popover: oklch(0.32 0 0);
--popover-foreground: oklch(0.985 0 0);
--primary: oklch(0.92 0 0);
--primary-foreground: oklch(0.205 0 0);
--secondary: oklch(0.38 0 0);
--secondary-foreground: oklch(0.985 0 0);
--muted: oklch(0.35 0 0);
--muted-foreground: oklch(0.72 0 0);       /* приглушённо-белый */
--accent: oklch(0.38 0 0);
--accent-foreground: oklch(0.985 0 0);
--destructive: oklch(0.78 0.191 22.216);   /* L=0.78, не 0.70 — иначе контраст
                                              с тинт-фоном бейджа впритык к AA */
--border: oklch(1 0 0 / 14%);              /* белый с малой альфой — линия
                                              читаема при любом фоне */
--input: oklch(1 0 0 / 16%);
--ring: oklch(0.556 0 0);
--sidebar: oklch(0.24 0 0);                /* сайдбар чуть темнее фона */
--sidebar-foreground: oklch(0.985 0 0);
--sidebar-accent: oklch(0.32 0 0);         /* hover/active = тон card */
--sidebar-accent-foreground: oklch(0.985 0 0);
--sidebar-border: oklch(1 0 0 / 12%);
--sidebar-ring: oklch(0.556 0 0);
--chart-1: oklch(0.87 0 0);
--chart-2: oklch(0.556 0 0);
--chart-3: oklch(0.439 0 0);
--chart-4: oklch(0.371 0 0);
--chart-5: oklch(0.269 0 0);
```

Логика ступеней: фон 0.272 → сайдбар 0.24 (темнее, отделяет навигацию) →
card/popover/sidebar-accent 0.32 (приподнятые поверхности) → muted 0.35 →
secondary/accent 0.38. Не выдумывать промежуточных значений без причины.

### 4.3. Светлая тема

**Цвета не трогать** — дефолтные shadcn-токены светлой темы остаются как есть.
Применяется только раздел 4.1 (Montserrat + базовые 16px).

### 4.4. Навигация — сайдбар для многораздельных сервисов

Если у сервиса **два и больше разделов верхнего уровня** (дашборды, списки,
настройки, отчёты — всё, что иначе стало бы «вкладками меню»), навигация
строится компонентом **`Sidebar`** из shadcn (`SidebarProvider` + `Sidebar` +
`SidebarInset`), а не верхним навбаром и не табами.

- Разделы — `SidebarMenu`/`SidebarMenuItem` с иконкой + подписью; активный
  раздел подсвечен (`isActive`). Группировка через `SidebarGroup` +
  `SidebarGroupLabel`, если разделов много.
- В шапке контентной части — `SidebarTrigger`; на десктопе сайдбар
  сворачиваемый (`collapsible="icon"`), мобильное поведение (offcanvas)
  компонент даёт из коробки — не изобретать своё.
- Токены `--sidebar-*` уже заданы: тёмная тема — раздел 4.2 (сайдбар чуть
  темнее фона), светлая — дефолтные shadcn.
- Компонент `Tabs` остаётся только для **локального** переключения внутри
  страницы (виды одной сущности, вкладки в карточке) — не для навигации
  между разделами приложения.
- Одноэкранным сервисам (форма, чат, один дашборд без разделов) сайдбар
  не навязывать — пустое меню из одного пункта хуже его отсутствия.

### 4.5. AI Elements — чат и всё AI-специфичное

**AI Elements** (`https://elements.ai-sdk.dev/docs`) — реестр компонентов
Vercel поверх того же shadcn/ui: код копируется в проект (по умолчанию в
`@/components/ai-elements/`), а не прячется в node_modules, и написан на тех
же семантических токенах. Значит фирменная тема из п. 4.1–4.3 ложится на него
**без правок** — перекрашивать компоненты руками не нужно.

**Когда брать оттуда, а не собирать самому.** Строим чат с LLM, ассистента,
агентский интерфейс, поток рассуждений, вывод вызовов инструментов — берём
готовое из AI Elements. Это основной источник для такого класса экранов:
самодельная лента сообщений с автоскроллом, стриминговым markdown и
состояниями тулколлов — это неделя работы и потом баги, которые там уже решены.

Что там есть (полный список — в доках, ниже ориентир):

| Задача | Компоненты |
|---|---|
| Лента диалога | `conversation`, `message`, `response`, `shimmer` |
| Ввод | `prompt-input`, `suggestion`, `attachments`, `speech-input`, `mic-selector` |
| Мышление и работа агента | `reasoning`, `chain-of-thought`, `task`, `plan`, `tool`, `agent`, `checkpoint` |
| Результаты и источники | `sources`, `inline-citation`, `code-block`, `artifact`, `snippet`, `jsx-preview`, `web-preview` |
| Инфраструктурное | `model-selector`, `context`, `sandbox`, `terminal`, `file-tree`, `test-results`, `stack-trace` |

Установка (тем же раннером, что и у проекта, — `npx` / `pnpm dlx` / `bunx --bun`):

```bash
npx ai-elements@latest add conversation message prompt-input
# то же самое через shadcn CLI, если удобнее один инструмент:
npx shadcn@latest add @ai-elements/message
```

Любая из этих команд сама доставит shadcn/ui, если его в проекте ещё нет.

Оговорки, которые надо проверить, а не предполагать:

- Доки заявляют prerequisites: Node 18+, React 19, **Next.js 14+ (App Router)**,
  AI SDK, Tailwind 4. Компоненты — обычный React + Tailwind, но если проект
  на Vite или React 18, не обещай пользователю, что всё встанет: поставь один
  компонент, собери, убедись — и только потом тащи остальные.
- Стриминг данных — это AI SDK и бэкенд, а не эти компоненты. Дизайн-скилл
  отвечает за внешний вид; за поток отвечает реализация бэкенда
  (`/nlab:code-design`, `/nlab:observability`).
- `AI_GATEWAY_API_KEY` / Vercel AI Gateway из доков — **не** наш дефолт: в
  NeuroLab LLM ходит через OpenAI-совместимый API, ключ берётся из env
  проекта. Не заводить аккаунты у Vercel по мотивам доков.
- Если поставлен скилл `ai-elements` — работать по нему (у него локальные
  справочники по каждому компоненту), доки в вебе — как источник правды по
  актуальному списку.

### 4.6. Ссылки пользователю — давать всегда

Пользователь чаще всего лучше агента знает, как должен выглядеть его экран, —
ему нужно дать выбрать. При первом же разговоре об интерфейсе (и каждый раз,
когда обсуждается «а что можно поставить / как это будет выглядеть»)
скидывай обе ссылки одним блоком:

> - **shadcn/ui** — база интерфейса (кнопки, формы, таблицы, сайдбар, диалоги):
>   https://ui.shadcn.com/docs/components
> - **AI Elements** — всё для чата с AI и агентов (лента сообщений, ввод,
>   рассуждения, вызовы инструментов): https://elements.ai-sdk.dev/docs
>
> Посмотрите и скажите, какие компоненты берём, — поставлю их и покрашу в
> нашу тему.

Правила подачи:

- обе ссылки, даже если задача выглядит «только чат» или «только админка» —
  выбор за пользователем, а не за агентом;
- ссылки — целиком, кликабельным URL, не «в документации shadcn»;
- в ответ на вопрос «а что вообще есть / какие ещё бывают компоненты /
  можно ли красивее» — сначала ссылки, потом своё предложение;
- одна короткая строка, зачем каждая: shadcn — интерфейс вообще,
  AI Elements — чат с AI. Не пересказывать содержимое сайтов.

## 5. Enforcement — обязательные правила (нарушение = блокировка)

| Правило | Технический механизм принуждения |
|---|---|
| UI строится только по оригинальному скиллу `shadcn` (его workflow и rules/), не по памяти | гейт на входе: скилл `shadcn` установлен (п.2), иначе стоп; при работе — он загружен через Skill tool |
| Никаких CDN/Google Fonts — шрифты только самохостом | проверка перед сдачей: в Network headless-браузера нет внешних запросов за шрифтами; grep по коду на `fonts.googleapis.com` / `fonts.gstatic.com` — 0 находок |
| Базовый размер — 16px, root не масштабируется | grep по css-файлам темы: `112.5%` (и любой другой root-`font-size` кроме `100%`) — 0 находок; в браузере `getComputedStyle(document.documentElement).fontSize` = `16px` |
| Никаких захардкоженных цветов вне семантических токенов | grep по `bg-white`, `text-black`, `bg-black`, `bg-blue-500`-подобным сырым значениям — 0 находок вне токенов |
| Контраст тёмной темы — WCAG AA | измерение, не «на глаз» (п.6 шаг 4): destructive/статусные бейджи ≥ 4.5:1 с запасом |
| Светлая тема не перекрашивается графитом | grep светлого блока темы: токены цветов не изменены относительно дефолтных shadcn |
| Многораздельный сервис (≥2 разделов верхнего уровня) — навигация через `Sidebar` | проверка перед сдачей: между разделами приложения не переключают `Tabs`/самодельный навбар; grep по app-уровню на `Tabs` в роли роутинга — 0 находок |
| Чат/агентские экраны — на компонентах AI Elements, не самописные | grep по коду чата: импорты из `@/components/ai-elements/*` есть; самодельной ленты сообщений (ручной автоскролл, свой рендер стриминга/тулколлов) нет. Исключение допустимо только с записанной в `NOTES.md` причиной |
| Ссылки на shadcn/ui и AI Elements выданы пользователю | в ответе, где обсуждались компоненты, присутствуют оба URL целиком (п. 4.6); отметка в `EVIDENCE.md` |

## 6. Процесс (шаги)

1. Проверь входные артефакты (п.2) и версию скилла в реестре (п.10).
   Скилла `shadcn` нет → стоп, инструкция по установке пользователю.
2. **Дай пользователю обе ссылки** (п. 4.6) и спроси, что берём, —
   до установки компонентов, а не после.
3. **Собери UI оригинальным скиллом `shadcn`**: загрузи его через Skill tool
   (`skill: "shadcn"`) и работай по нему — сначала
   `npx shadcn@latest info --json` (или `init`, если проекта ещё нет —
   стиль по умолчанию `base-nova`), потом поиск/установка компонентов.
   Его правила композиции обязательны — семантические токены,
   `Field`/`FieldGroup` для форм, `gap-*` вместо `space-y-*` и т.д.
4. Если в интерфейсе есть чат/ассистент/агентские экраны — их части бери
   из **AI Elements** (п. 4.5): скилл `ai-elements` через Skill tool, если
   установлен, иначе CLI + доки. Ставь их в тот же проект, поверх той же
   темы.
5. Примени правки NeuroLab: раздел 4.1 — в обеих темах, раздел 4.2 —
   только в тёмной, раздел 4.3 — светлая остаётся стандартной. Компоненты
   AI Elements отдельной покраски не требуют — но проверь их в тёмной теме
   вместе со всеми (шаг ниже).
6. Проверка перед сдачей:
   1. Контраст — не на глаз: destructive/статусные бейджи на тёмном фоне
      ≥ 4.5:1 (WCAG AA) с запасом; getComputedStyle отдаёт oklch-строку как
      есть, поэтому при сомнении рендерить цвет через canvas + getImageData
      и считать по WCAG-формуле. Ориентиры: foreground/background 14.3:1,
      muted-foreground 6:1, destructive-бейдж 5.15:1.
   2. Скриншот в headless Chrome обеих тем (если в проекте есть

## 10. Авто-обновление

`update_check: per_session` — при первом использовании скилла в сессии
сверь локальную `version` с реестром `registry_url`:

| Разница версий | Действие |
|---|---|
| Совпадает | работать дальше молча |
| Патч/минорная | подтянуть автоматически + одна строка уведомления |
| Мажорная | не обновлять, спросить подтверждение — возможны ломающие изменения |
| Реестр недоступен | работать на локальной версии, отметить в `EVIDENCE.md`: «проверка обновления не выполнена» |

Зависимости `shadcn` и `ai-elements` обновляются своим апстримом — их версии
не проверять, достаточно факта установки (п.2); актуальный список компонентов
AI Elements всегда смотреть на `https://elements.ai-sdk.dev/docs`, а не по
памяти.

**Обратная связь в реестр.** Наткнулся на то, чего в скилле нет или что в нём
неверно — API отвечает не так, как описано, шаг не проходит, нашлась грабля,
есть что улучшить — не молчи и не правь локальную копию: заведи issue в реестре
и продолжай работу обходным путём. Сначала поищи существующее
(`gh issue list -R vibe-nlab/nlab-vibeskills -S "<ключевые слова>"`), одна
проблема — одно issue:

```bash
gh issue create -R vibe-nlab/nlab-vibeskills -l skill-feedback \
  -t "<скилл> <версия>: <суть в одну строку>" \
  -b "<что ожидал; что произошло (ошибка дословно); как воспроизвести; предложение>"
```

Без секретов и содержимого чужих проектов. Ссылку на issue запиши в `NOTES.md`
проекта и одной строкой скажи пользователю. Нет `gh` — сформулируй текст issue
пользователю, пусть заведёт сам.

## 11. Чего НЕ делать

- Не подключать Google Fonts / любые CDN (самохост обязателен).
- Не задирать root `font-size` (`112.5%`, `18px` и подобное) — базовый размер
  16px; правило укрупнения отменено в v1.3.0, старые проекты приводить к 16px
  при первой же правке дизайна.
- Не менять светлую тему цветами графита — она остаётся стандартной shadcn.
- Не занижать destructive до дефолтного L=0.70 на графитовом фоне.
- Не добавлять логотипы/эмблемы в шапки и формы входа без явной просьбы —
  текстовых заголовков достаточно.
- Не строить навигацию верхнего уровня табами или самодельным навбаром,
  когда разделов два и больше, — это сайдбар (п.4.4). И наоборот: не вешать
  сайдбар на одноэкранный сервис.
- Не копировать shadcn-доки внутрь этого скилла «для надёжности» — источник
  правды один: установленный оригинальный скилл `shadcn`. То же про
  AI Elements: список компонентов — на сайте и в скилле `ai-elements`,
  а не копией здесь.
- Не писать чат с AI с нуля (своя лента сообщений, свой автоскролл, свой
  рендер стриминга и тулколлов), когда в AI Elements это уже есть.
- Не молчать про ссылки: обе (ui.shadcn.com и elements.ai-sdk.dev) идут
  пользователю до того, как агент начал выбирать компоненты за него.
- Не перекрашивать компоненты AI Elements руками — они на тех же
  семантических токенах, тема применяется сама; правки цвета внутри
  компонента означают, что где-то захардкожен цвет.
- Не тащить из доков AI Elements их дефолты по инфраструктуре — Vercel AI
  Gateway и `AI_GATEWAY_API_KEY` не наш стек; LLM у нас через
  OpenAI-совместимый API.

**Выход**: обе ссылки пользователю (п. 4.6) и вопрос, что берём; Vite-проект,

«0 находок»; коммит.

**Вход-2**: «сделай чат с нашим агентом, в стиле nlab».

единой правки внутри компонентов; сайдбара нет — экран один; проверки п.6,
запись в `EVIDENCE.md`, коммит.
