# /nlab:design — спецификация и архитектура проекта

Второй этап Golden Path. Берёт результат `/nlab:start` и превращает
намерение в спроектированную систему: закрывает спецификацию и
раскладывает бэкенд. После него можно писать код, не догадываясь ни о
контрактах, ни о том, куда что класть.

Два вопроса — две папки внутри `project-docs/`:

| Папка | Вопрос | Что внутри |
|---|---|---|
| `spec/` | **что** система делает | `SPEC.md` (индекс), `schemas.md` (модели вход/выход), `tools.md` (контракты инструментов), `agents.md` (схема агентов) |
| `arch/` | **куда** что кладём | `ARCH.md` (слои, порты, карта модулей), `language.md` (единый язык домена), `adr/` (решения с обоснованием) |

SDD и DDD здесь не конкурируют, а работают в паре: спецификация даёт
понятия и контракты, DDD раскладывает их по коду, а единый язык из
`arch/language.md` общий для обоих — одно понятие называется одинаково в
разговоре с заказчиком, в спецификации и в именах классов.

## DDD по размеру задачи

Скилл не навязывает полный DDD маленькому сервису:

| Уровень | Когда |
|---|---|
| слои `domain` / `application` / `infrastructure` + единый язык | всегда, это минимум |
| + агрегаты и репозитории | есть инварианты, которые нельзя нарушить частичной записью |
| + границы доменных областей | доменных областей больше одной, одно слово значит разное |

Выбранный уровень и причина фиксируются в `arch/ARCH.md` и в ADR. Поднять
уровень позже дешевле, чем разбирать преждевременную конструкцию.

## Установка

Скилл входит в плагин `nlab` — ставится вместе со всем пакетом. См.
[README реестра](../../README.md).

## Использование

1. Откройте Claude Code в проекте, который уже прошёл `/nlab:start`.
2. Наберите `/nlab:design`.
3. Отвечайте на вопросы про предметную область — своими словами: как
   называются вещи, чем одно отличается от другого. Именно из этого
   собирается единый язык, а из него — имена в коде.
4. На выходе — заполненные `spec/` и `arch/`, скелет папок бэкенда и
   подзадачи, привязанные к разделам спецификации.

## Что проверяется автоматически

Правила без механической проверки остаются просьбами, поэтому:

| | Что ловит |
|---|---|
| **H** | остались `TODO` — статус не переводится в `design` |
| **I** | критерий приёмки не покрыт подзадачей, или ссылка ведёт в никуда |
| **J** | модели в `spec/schemas.md` не компилируются — значит, это не спецификация |
| **K** | домен импортирует БД, HTTP или SDK — слои спроектированы неверно |
| **L** | в схеме агентов стрелка ведёт к необъявленному узлу |
| **M** | ADR написан, но нигде не упомянут — решение принято и потеряно |
