# /nlab:observability — трейсинг агентов в общий MLflow

Скилл для Claude Code. Подключает проект с pydantic-ai-агентами к
обсервабилити NeuroLab: каждый запуск агента пишется трейсом в общий
MLflow-сервер — видно промпт, сообщения, вызовы LLM/инструментов/MCP,
ответ и токены. Юзер-инпуты привязываются к трейсам тегами
session/user.

Многошаговая система (конвейер, мультиагентная связка, диалог) даёт **один
трейс на запуск**, а не по трейсу на шаг: в UI видно всё дерево — что за чем
идёт, где шаги идут параллельно, где сходятся обратно. В строке списка сразу
видны вход и исход запуска, а не пустое место.

Трейс виден **по ходу запуска**, а не только в конце: закрытый шаг доезжает до
сервера примерно за полсекунды, а сам трейс появляется в списке со статусом
«идёт» ещё до финала — на длинном конвейере видно, где вы сейчас. Замеряется
скриптом из комплекта ([assets/realtime_probe.py](assets/realtime_probe.py)).

Трейс пишется по **контракту мониторинга v1**: шаг — спан типа AGENT с
атрибутами `nlab.step.id` / `title` / `after`, на трейсе — `nlab.schema` /
`nlab.mode` / `nlab.service`. Благодаря этому запуск разбирает не только UI
MLflow, но и внешний вьюер лаборатории — одинаково для любого проекта, не зная
его устройства. Выполнен ли контракт, показывает гейт из комплекта
([assets/check_contract.py](assets/check_contract.py)): он читает готовый трейс
с сервера и печатает, чего в нём не хватает и чем это обернётся в картинке.
Связи между шагами вьюер берёт только из `nlab.step.after`: не записаны — рисует
шаги без стрелок, а не догадку по времени.

Проверить интеграцию можно **бесплатно**: в комплекте заглушка LLM-роутера
([assets/fake_llm_router.py](assets/fake_llm_router.py)) — полный боевой путь
(SDK, HTTP, инструментация) при нулевом расходе токенов. Живая модель нужна
только чтобы оценить качество ответов, для проверки трейсинга — нет.

## Установка

Скилл входит в плагин `nlab` — ставится вместе со всем пакетом.
См. [README реестра](../../README.md).

## Использование

1. Откройте Claude Code в корне проекта (бэкенд с агентами уже должен
   существовать).
2. Наберите `/nlab:observability`.
3. Claude добавит `mlflow` в зависимости, создаст
   `backend/infrastructure/tracing.py`, пропишет `MLFLOW_TRACKING_URI`
   в env-файлы и проверит работу на живом вызове агента.

## Адрес сервера и доступ

Общий сервер — `https://mlflow.a.nlabstudio.ru`, закрыт логином/паролем.
Адрес и правила доступа живут в
[references/mlflow-server.md](references/mlflow-server.md); сами логин и
пароль — в Vault (`secret/platform/mlflow`), откуда Claude забирает их
по вашему личному токену Vault и кладёт только в `.env` проекта. Токен
выдают [@sanchezgl](https://t.me/sanchezgl) или
[@KirillBorovkov](https://t.me/KirillBorovkov) (руками или через бота).
Пока токена нет, `MLFLOW_TRACKING_URI` остаётся пустым — трейсинг просто
выключен, приложение работает как обычно; значения потом вписываются в env
без правок кода. Реестр публичный: паролей в нём нет и не будет.
