# nlab-vibeskills — скиллы NeuroLab для вайб-кодинга

Набор скиллов для Claude Code, с которым любой сотрудник лаборатории —
разработчик или человек без кода — собирает своего агента или сервис так,
чтобы тот сразу вписался в общую систему лаборатории. Ставится одним
пакетом (плагин `nlab`), начало любого проекта — команда
`/nlab:project-start`.

## Какую проблему это решает

Когда каждый собирает агентов сам по себе, получается зоопарк:

- **Разные фреймворки.** Агенты делаются в разных, никем не
  контролируемых фреймворках — сопровождать и развивать их общими силами
  невозможно.
- **Разный дизайн.** У каждого интерфейса свой вид — такие агенты потом
  не встроить в общий каталог агентов лаборатории.
- **Непонятно, как деплоить.** Никто не знает, как и где это запускать —
  проекты остаются жить на ноутбуках авторов.
- **Чёрный ящик.** Нет мониторинга и сбора логов: не видно, какие промпты
  уходили, что и откуда вызывалось, — работу агента нельзя контролировать.

Скиллы решают это end-to-end. Вы вместе с агентом проектируете прототип
своей системы, а дальше он сам, по своим инструкциям:

- соберёт **бэкенд по единой схеме** лаборатории (один общий фреймворк
  агентов, единые правила проектирования);
- соберёт **фронтенд по единой схеме и в фирменном стиле лабы** — такой
  интерфейс потом спокойно внедряется в любую из систем лаборатории;
- подключит **систему мониторинга**: вы и ваши пользователи видите, что,
  где и откуда вызывалось, какие промпты и ответы были внутри, — агент
  перестаёт быть blackbox'ом;
- **задеплоит всё на серверах лаборатории** — сервис сразу собран,
  доступен по своему домену и работает.

## Как этим пользоваться

Всё, что нужно сделать, — инициализировать проект командой
`/nlab:project-start`. Дальше агент ведёт сам:

1. **Спросит, кто вы** — технический специалист или нет, — и от этого
   строит все свои объяснения: разработчику — термины и диффы, обычному
   человеку — простыми словами.
2. **Уточнит требования** — что должно получиться и как поймём, что
   получилось.
3. **Соберёт с вами прототип** — кликабельный макет интерфейса. На нём
   проще всего увидеть, что вы хотите: добавить новые функции и фичи в
   виде заглушек, поправить и утвердить, как ваша платформа или агент
   будет выглядеть и что делать.
4. **Спроектирует и соберёт систему** по утверждённому прототипу — по
   заданным единым алгоритмам и параметрам лаборатории.
5. **Подскажет, как одной командой всё задеплоить** — залить на GitHub и
   выложить на сервер лаборатории с доменом и мониторингом.

## Скиллы — что для чего

| Скилл | Команда | Что делает, человеческим языком |
|---|---|---|
| `project-start` | `/nlab:project-start` | старт любого проекта: пара вопросов о том, что вы хотите получить, каркас проекта и план простым языком |
| `prototype` | `/nlab:prototype` | кликабельный макет будущего интерфейса: смотрите, правите, утверждаете — макет и становится техзаданием |
| `code-design` | `/nlab:code-design` | проектирует «внутренности»: как устроены бэкенд и агенты, чтобы систему потом можно было развивать и встраивать в общую |
| `design-ui` | `/nlab:design-ui` | фирменный стиль NeuroLab для интерфейса — ваш сервис выглядит как остальные системы лаборатории |
| `observability` | `/nlab:observability` | мониторинг агента: в общем MLflow видны промпты, вызовы инструментов и ответы — не чёрный ящик |
| `dokploy-prep` | `/nlab:dokploy-prep` | готовит репозиторий к деплою: конфиги и инструкция, чтобы выложить сервис без доработок |
| `dokploy` | `/nlab:dokploy` | деплоит на сервер лаборатории: сборка, домен — сервис сразу доступен по ссылке |

Внешняя зависимость, которая ставится отдельно (не входит в пакет):
`shadcn` — официальный скилл shadcn/ui, обязателен для `/nlab:design-ui`.

## Установка

Репозиторий приватный: нужен доступ на чтение к `vibe-nlab/nlab-vibeskills`
и настроенный git (`gh auth login` или SSH-ключ). Claude Code клонирует его
обычным `git` под вашей учётной записью — публиковать ничего не требуется.

В Claude Code:

```
/plugin marketplace add vibe-nlab/nlab-vibeskills
/plugin install nlab@nlab-vibeskills
```

Проверить: `/plugin` → плагин `nlab` в списке установленных; скиллы
появятся как `/nlab:<имя>`.

Если по HTTPS не проходит авторизация, добавьте маркетплейс по SSH:

```
/plugin marketplace add git@github.com:vibe-nlab/nlab-vibeskills.git
```

### Обновление

```
/plugin marketplace update nlab-vibeskills
```

### Удаление

```
/plugin uninstall nlab@nlab-vibeskills
```

## Что ещё в репозитории

| Путь | Назначение |
|---|---|
| `.claude-plugin/` | манифесты плагина и маркетплейса |
| `skills/` | сами скиллы (каждый — папка с `SKILL.md`) |
| `skills-doc/` | как писать скиллы: `skill_template.md`, `skill_design_best_practices.md` и `validate_skills.py` |

Каждый скилл самодостаточен: всё, что ему нужно, лежит в его же папке —
`assets/` (копируется в проект пользователя) и `references/` (только
чтение). Корень репозитория остаётся чистым. Например, правила процесса
`AGENTS.md`, конвенции стека `project_setup_best_practices.md` и стартовый
фронтенд-темплейт живут внутри `skills/project-start/`.

## Как добавить скилл в пакет

1. Создайте `skills/<имя>/SKILL.md` по шаблону `skills-doc/skill_template.md`.
2. Поле `name:` во frontmatter должно совпадать с именем папки — оно же
   станет командой `/nlab:<имя>`.
3. Проверьте перед коммитом:

   ```bash
   python3 skills-doc/validate_skills.py   # frontmatter, имена, зависимости
   claude plugin validate . --strict       # манифесты плагина
   ```

   Нужны оба: `claude plugin validate` разбирает только манифесты и не
   заглядывает в YAML внутри `SKILL.md` — сломанный frontmatter он пропустит.
4. Поднимите `version` в `.claude-plugin/plugin.json` и
   `.claude-plugin/marketplace.json`, закоммитьте и запушьте.
5. У пользователей: `/plugin marketplace update nlab-vibeskills`.
