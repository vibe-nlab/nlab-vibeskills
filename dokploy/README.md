# /dokploy — деплой и эксплуатация сервисов на Dokploy

Скилл для Claude Code: деплой-агент для ваших Dokploy-серверов. Деплоит
приложения из GitHub через Dokploy API (проект → compose → env → домены →
deploy → health-проверка), делает redeploy, читает логи, диагностирует упавшие
сервисы, обновляет env и домены.

## Что нужно подготовить (спросит при первом запуске)

1. **Dokploy-сервер** — установленная панель Dokploy и её URL
   (`http://<ip>:3000` или свой домен).
2. **API-ключ** — Dokploy UI → Settings → API/CLI → Generate. Скилл проверит
   его первым же запросом.
3. **GitHub App в Dokploy** — Settings → Git → GitHub. Без этого деплой из
   приватных репозиториев не работает.
4. **Wildcard-домен** (желательно) — A-запись `*.ваш-домен.ру` → IP сервера,
   чтобы скилл заводил поддомены с автоматическим TLS. Без домена деплой
   тоже возможен, но без HTTPS-роутинга.
5. Опционально — **SSH-доступ** к серверу (только чтение: логи контейнеров).

Всё это скилл спросит сам при первом подключении сервера и запишет в локальный
реестр `servers.md` (по шаблону `servers.example.md`).

**Важно:** `servers.md` содержит ваши API-ключи. Он создаётся локально у вас и
не должен попадать в git, пересылки и любые копии скилла.

## Установка

1. Скопируйте папку целиком в скиллы Claude Code:

   ```bash
   cp -r dokploy ~/.claude/skills/dokploy
   ```

2. Добавьте в `~/.claude/CLAUDE.md` (создайте файл, если его нет):

   ```markdown
   # dokploy
   - **dokploy** (`~/.claude/skills/dokploy/SKILL.md`) — деплой и эксплуатация
     сервисов на Dokploy-серверах. Trigger: `/dokploy`
   When the user types `/dokploy`, invoke the Skill tool with
   `skill: "dokploy"` before doing anything else.
   ```

## Использование

1. Откройте Claude Code в репозитории проекта, который хотите задеплоить.
2. Наберите `/dokploy` и скажите, что нужно: «задеплой этот проект»,
   «сделай redeploy», «почему упал сервис X», «добавь домен».
3. При первом запуске скилл сначала разберётся в репозитории, затем спросит
   доступы к серверу (URL, API-ключ и т.д.) — дальше всё делает сам через
   Dokploy API и отчитывается таблицей: домены, статусы, где лежат креды.

Если репозиторий ещё не готов к Dokploy (нет `docker-compose.dokploy.yml`),
скилл подготовит его сам — или используйте парный скилл `/dokploy-prep`,
который делает только подготовку без деплоя.

## Состав

| Файл | Назначение |
|---|---|
| `SKILL.md` | сам скилл: онбординг сервера, правила, сценарии деплоя и эксплуатации |

| `references/api.md` | проверенный справочник Dokploy API с рабочими payload'ами |
